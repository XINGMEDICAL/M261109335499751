XINGMEDICAL — Conector World Office a Odoo.sh 20
================================================
ESTADO: paquete preparado para instalar y validar. NO se ha instalado en Odoo,
NO se ha ejecutado una carga completa y NO hay una tarea programada instalada.

CONTENIDO
- xing_wo_sync/: modulo Odoo 20, sin claves ni nombres del servidor SQL.
- windows/Sync-WorldOffice.ps1: cliente PowerShell 5.1, sin dependencias SQLite.
- windows/Test-SyncClient.ps1: validaciones locales con datos ficticios.
- descubrir_activos_wo.sql: descubre estructura, NO registros de activos.
- tests/: 20 pruebas locales independientes del ORM.

ALCANCE IMPLEMENTADO
1. Productos: TODOS los productos activos de PRODUCTOS NO FABRICADOS POR LA
   EMPRESA y TODOS los servicios activos de SERVICIOS (alcance SQL previamente
   acordado). No incluye otros grupos hasta definir su correspondencia.
   Crea y actualiza nombre, codigo y categoria. No modifica fotos, descripciones
   comerciales, precios, impuestos, costos, unidades, existencias ni seriales
   de inventario. Los registros nuevos heredan los valores por defecto de Odoo
   para los campos no incluidos. Revisarlos antes de vender/facturar.
   Si un producto existente cambia de tipo/seguimiento, se bloquea para revision.
   Los productos compartidos entre empresas no se modifican automaticamente.
2. Empleados: TODOS los terceros con la propiedad exacta Empleado, combinada
   o no con otras propiedades. Nombre completo e identificacion de World Office.
   IdTercero es la clave estable dentro de la base de origen. La identificacion
   se conserva en un campo privado propio wo_identification: NO se sobrescriben
   los contratos/versiones de Odoo 20 ni sus datos personales estandar.
   Si ya existe un empleado con documento coincidente se vincula solo si es
   unico y pertenece a la empresa seleccionada. Mismo nombre sin identidad
   comprobable se bloquea. No crea usuarios/licencias de acceso de Odoo.
   No importa salario, bancos, fechas de contrato, bajas, familiares o correos.
   Cargo, centro de costos y contacto requieren validar la vista auxiliar/join.
3. Activos: destino implementado como maintenance.equipment (Mantenimiento).
   Campos: nombre, codigo de activo World Office y serie cuando exista.
   NO son activos contables, NO generan depreciaciones ni asientos.
   Origen confirmado: Vista_Tabla_Inventarios, grupo ACTIVOS FIJOS, Activo=-1,
   clasificaciones Activo Fijo y Producto. Incluye los 206 + 6 = 212 registros
   reportados al 14/11/2026. El total puede variar en siguientes ejecuciones.
   Cada CodigoInventario representa un activo fisico individual (confirmado).
   IdInventario mantiene el vinculo; CodigoInventario se guarda como wo_asset_code.
   La descripcion se guarda como nombre del equipo. No se inventa numero de serie:
   la fuente de series aun no esta confirmada. Una serie vacia no borra la de Odoo.
   No se asignan responsables, ubicaciones, categorias ni planes de mantenimiento
   hasta validar esos campos de origen. Dos equipos con descripcion identica y
   codigos distintos se mantienen separados.


PROTECCIONES
- Simulacion por defecto: no escribe ni vinculos ni registros de negocio.
- -Apply mas confirmacion SINCRONIZAR-1 habilita escritura para empresa 1.
- Cada peticion envia maximo 50 registros; cada fila tiene su propio savepoint.
- La fila y su vinculo se guardan en la MISMA transaccion dentro de Odoo.
- Repetir la misma fuente/empresa no debe duplicar registros.
- No se borra, archiva, reactiva ni se ajusta inventario automaticamente.
- Una falta de respuesta HTTP no se reintenta automaticamente: algunos lotes
  podrian haberse confirmado. Repetir con el mismo identificador de fuente
  permite reencontrarlos sin reutilizar IDs de otra base/demo.
- El identificador de fuente se deriva de servidor + base SQL. No cambiarlo
  arbitrariamente. Cambios de instancia/anio requieren revisar el alcance.
- Los duplicados se revisan sobre TODO el resultado SQL antes de partir lotes.
  Las filas invalidas se omiten y se informa su ID y motivo, sin documento/nombre.
- Los datos HR viajan solo por HTTPS a la base indicada. Los logs del conector
  evitan nombres, documentos, salarios y credenciales.
- El modulo NO usa sudo para saltarse permisos. Requiere acceso de administrador
  del conector y permisos reales a productos, empleados y equipos. No concede
  acceso a usuarios nuevos ni amplia permisos automaticamente.

INSTALACION — PRIMERO EN STAGING
1. Mantener un respaldo reciente de produccion descargado.
2. En Odoo.sh crear una rama de Staging basada en main para instalar/probar.
   Con el plan mostrado hay una rama de pruebas disponible.
3. Agregar SOLO la carpeta xing_wo_sync a la raiz del repositorio GitHub de esa
   rama (o a su directorio de addons ya configurado). No subir el ZIP como si
   fuera un modulo, ni los archivos Windows, exportaciones o credenciales.
4. Dejar terminar el build. En Aplicaciones, actualizar la lista de modulos
   (modo desarrollador si es necesario), quitar el filtro Aplicaciones y buscar
   XINGMEDICAL - World Office Sync. Instalarlo.
   Instala sus dependencias: Inventario, Empleados y Mantenimiento.
5. Probar los tests de integracion en una build de pruebas:
   --test-tags /xing_wo_sync
   Estan incluidos en xing_wo_sync/tests/. No ejecutar pruebas contra produccion.
6. En Windows ejecutar .\Test-SyncClient.ps1 (sin claves ni conexion de red).
7. Probar simulacion apuntando a la URL DE STAGING con -OdooUrl.
   Una copia neutralizada puede requerir generar alli una clave de prueba.
8. Revisar resultados y ejecutar carga en STAGING. Repetir: deberia mostrar
   unchanged/linked y no crear duplicados. Revisar empleados y equipos desde UI.
9. Tras validar, pasar el codigo a main. La instalacion realizada en la base
   de Staging NO se transfiere como datos a produccion: instalar tambien el
   modulo en la base de produccion y revisar nuevamente antes de -Apply.

USO EN WINDOWS (tras instalar el modulo)
Guardar windows/ en la carpeta de desarrollo del servidor que accede a SQL.
No pegar claves en la linea de comandos. Preparar el comando, copiar la clave
API al portapapeles del equipo Windows y presionar Enter SIN pegarla.
Cuando lo pida, copiar la contrasena SQL y volver a presionar Enter SIN pegarla.

Simular los TRES flujos: productos del alcance, empleados y activos, empresa 1:
  .\Sync-WorldOffice.ps1 -UseClipboard -SqlPasswordFromClipboard -CompanyId 1

Aplicar (solo con respaldo, simulacion revisada y modulo probado):
  .\Sync-WorldOffice.ps1 -UseClipboard -SqlPasswordFromClipboard -CompanyId 1 -Apply

Usar otra base Odoo (p. ej. staging):
  agregar -OdooUrl "https://URL-DE-STAGING.dev.odoo.com"

Solo productos: agregar -Scope Products
Solo empleados: agregar -Scope Employees
Solo activos: agregar -Scope Assets
Productos y empleados sin activos: -Scope ProductsEmployees
Los tres flujos: -Scope All (predeterminado)

VERIFICACION DE ACTIVOS EN SSMS
El archivo validar_activos_wo.sql comprueba el alcance y muestra solo cantidades,
no nombres ni series. No modifica registros. Si hay codigos o IDs duplicados,
el conector los omite para revision, sin agrupar varios activos en un equipo.

REPETICION Y PROGRAMACION
La sincronizacion se puede repetir ejecutando el mismo comando. En esta version
es interactiva y no guarda claves. No se ha creado una tarea de Windows ni una
frecuencia automatica. Para ejecucion desatendida se necesita definir frecuencia,
cuenta de servicio, almacenamiento local seguro de secretos y alertas.
